## 0. 为什么选择 WSL2

个人理解：Windows PowerShell 与常见 Linux Agent 工程实践在命令和环境上有差异；WSL2 能提供 Bash、APT、Linux 文件权限和隔离程度更高的开发空间。我的目标不是在 WSL2 里装一个完整桌面作为日常系统，而是在 Windows 上打开浏览器/编辑器，AI Agent 在 Linux 工作目录执行命令，最终跑通 ROS 2、LeRobot、PushT，并逐步扩展 Isaac Sim。

## 1. Windows 端：检查虚拟化和安装 WSL

原始操作记录：

~~~powershell
wsl --install --web-download
wsl --update
wsl
~~~

`--web-download` 表示从在线源下载而非通过 Microsoft Store，普通 `wsl --install` 默认可安装 Ubuntu；实际默认发行版及系统状态需以输出为准。

建议做一次完整自查（PowerShell）：

~~~powershell
wsl --version
wsl --status
wsl --list --online
wsl --list --verbose
~~~

如需显式指定版本和安装目录，先检查自己当前 WSL 是否支持对应参数（`wsl --help`）：

~~~powershell
# 不要把 -l -o 与 --location 混在一起
wsl --list --online

# 新安装：名称、发行版、位置都要按本机实际情况填写
wsl --install -d Ubuntu-24.04 --location D:\wsl\Ubuntu24.04

# 已有 Ubuntu22.04 则不要直接覆盖
wsl -d Ubuntu-22.04
wsl --set-default Ubuntu-22.04
~~~

> **纠错**：`wsl -l -o --location D:\wsl\Ubuntu22.04` 不是“列出在线版本同时指定安装位置”的正确写法；`wsl -d`、`wsl --set-default` 后面必须指定发行版名称。`wsl --install Ubuntu --name` 也缺少名称值；具体旗标请按 `wsl --help` 判断。

第一次进入 Ubuntu 后设置 Linux 用户名与密码；建议执行：

~~~bash
cat /etc/os-release
uname -r
whoami
pwd
~~~

### Windows 端补充

- BIOS/UEFI 要开启 CPU 虚拟化（Intel VT-x/AMD SVM）。
- 若 `wsl --update` 因 403 失败，先检查微软官方更新途径、网络/代理或尝试 `wsl --update --web-download`；**不要**因失败就安装来源不明的补丁包。
- WSL 所在磁盘、Windows 系统盘与未来模型权重/数据集存放位置要预留空间。

## 2. Ubuntu 22.04 换国内 APT 镜像

个人原笔记是在 `/etc/apt/sources.list` 用 vim 把 Ubuntu 地址换成清华镜像：

~~~bash
sudo vim /etc/apt/sources.list
# 按 i 进入插入模式，Esc 后输入 :wq 保存退出
~~~

推荐把“备份 → 修改 → 核查 → 更新”完整记录下来：

~~~bash
cat /etc/os-release
sudo cp /etc/apt/sources.list /etc/apt/sources.list.bak
sudo sed -i \
  -e 's|http://archive.ubuntu.com/ubuntu/|https://mirrors.tuna.tsinghua.edu.cn/ubuntu/|g' \
  -e 's|http://security.ubuntu.com/ubuntu/|https://mirrors.tuna.tsinghua.edu.cn/ubuntu/|g' \
  /etc/apt/sources.list
grep -E '^(deb|# deb)' /etc/apt/sources.list | head -30
sudo apt update
~~~

请查看是否仍有 `jammy`、`jammy-updates`、`jammy-security` 以及所需 `universe` 仓库。若使用的原地址是其他域名，请修改 `URIs`/对应行而不是盲目替换。

**Ubuntu 24.04 的重要区别**：通常采用 `/etc/apt/sources.list.d/ubuntu.sources` 的 deb822 格式，需要按 24.04 专门配置；不要把上面的 22.04 命令照搬到 24.04。

参考：[清华 Ubuntu 镜像帮助](https://mirrors.tuna.tsinghua.edu.cn/help/ubuntu/)。

## 3. Linux 可视化：XFCE + XRDP 试验，以及更合适的 WSLg

个人补充记录曾尝试：

~~~bash
sudo apt install xfce4 xfce4-goodies xrdp -y
echo "stratxfce4" > ~/.xsession
sudo systemctl enable xrdp
sudo systemctl start xrdp
hostname -I
~~~

在 Windows 用 `Win + R` → `mstsc` 连接 WSL IP，出现了“连接后闪退”的问题，于是记录过：

~~~bash
sudo adduser xrdp ssl-cert
sudo systemctl restart xrdp
~~~

**必须纠正：**

1. `stratxfce4` 是拼写错误，正确命令是 `startxfce4`：
   ~~~bash
   printf '%s\n' 'startxfce4' > ~/.xsession
   cat ~/.xsession
   ~~~
2. `hostname -I#然后...` 应分成命令与独立注释行，否则容易出错。
3. 加入 `ssl-cert` 组和重启 `xrdp` **不等于已经解决闪退**。还可能涉及桌面会话、端口、systemd、Xorg、WSL 网络等问题。
4. XRDP 可能要求检查监听端口、防火墙和 WSL IP 变化；不要直接把 RDP 端口开放到公网。
5. 对本项目中的 `xeyes`、RViz2、PushT 一类 Linux GUI，**先测试 WSLg**，不必把完整 XFCE/XRDP 当作前提。

WSLg 建议验证：

~~~bash
echo "$DISPLAY"
echo "$WAYLAND_DISPLAY"
sudo apt update && sudo apt install -y x11-apps mesa-utils
xeyes
glxinfo -B
~~~

若普通 GUI 能弹出 Windows 窗口，先用 WSLg 进行机器人仿真可视化。**WSLg 成功不代表 Isaac Sim 的完整 RTX/Vulkan GPU 图形功能受到支持**；Isaac Sim 优先使用官方支持的 Windows 原生安装。

## 4. Git / Python / Node.js：Agent 之前的三件套

个人笔记中记有：

~~~bash
git -v
python3 --version
sudo apt update
sudo apt install python-is-python3
node -v
npm -v
~~~

建议修正/扩展：

~~~bash
sudo apt install -y \
  git git-lfs curl wget ca-certificates \
  build-essential python3-pip python3-venv \
  python-is-python3
git --version
git lfs install
python3 --version
python --version
node --version
npm --version
~~~

`python-is-python3` 只把 `python` 命令指向 Python 3，**不会**替你创建项目虚拟环境。

### Git 主机配置检查与选择性同步

原始记录提到“要求 AI 知道自己在 WSL、读取宿主机 git 设置并同步到 WSL”。建议由 Agent **先只读对照**，确认后再写：

~~~bash
git config --global --list --show-origin
git config --global user.name
git config --global user.email

# 只读检查 Windows Git 全局配置（文件可能不存在）
test -f /mnt/c/Users/<Windows用户名>/.gitconfig && \
  sed -n '1,120p' /mnt/c/Users/<Windows用户名>/.gitconfig
~~~

避免直接复制 Windows `credential.helper`、Windows 专属路径、Token 或 SSH 私钥。身份信息可以按本人确认设置：

~~~bash
git config --global user.name "你选择的提交署名"
git config --global user.email "你选择的提交邮箱"
~~~

**GitHub 的仓库授权/登录与 Git 提交署名不是同一个概念。** 不需要在笔记中保存私有 Token。

### Node.js 建议：nvm 单独管理 Linux 版本

DSH 需要兼容的新 Node.js。使用 [nvm 官方安装说明](https://github.com/nvm-sh/nvm) 在 **WSL 内**安装 nvm，重新打开 Bash 后：

~~~bash
command -v nvm
nvm install 22
nvm use 22
node --version
npm --version
~~~

要确保实际 Node 22 的小版本满足 DSH 当前最低要求（建议 `22.19.0+`），或者使用 Node 24 LTS 兼容版；检查 `npx @deepseek-ai/dsh --help` 以确认本机可运行。

中国大陆网络可以临时配置 npm 镜像：

~~~bash
npm config set registry https://registry.npmmirror.com
npm config get registry
# 遇到包版本同步问题时可恢复官方源
npm config set registry https://registry.npmjs.org
~~~

## 5. 工作目录：统一放在 Linux 文件系统内

个人笔记中准备：

~~~bash
cd ~
mkdir vla
~~~

建议沿用个人命名，让 Agent 和后续训练都在固定位置工作：

~~~bash
mkdir -p ~/vla/{lerobot,pusht,ros2_ws,isaac,experiments,notes}
cd ~/vla
pwd
explorer.exe .
~~~

`explorer.exe .` 可从 Windows 文件管理器查看 WSL 当前目录。大型 Conda 环境、ROS build 文件和训练 checkpoint 尽量存放在 WSL 的 Linux 文件系统内，避免大量小文件存于 `/mnt/c`。

**给 Agent 的环境说明（可写入 `~/vla/AGENTS.md`）：**

~~~markdown
# WSL Robotics Workspace
- 当前主机为 Windows 11，执行环境是 WSL2 Ubuntu / Bash。
- 所有机器人算法项目统一放在 ~/vla；不要擅自切换到 Windows PowerShell。
- 在变更系统包、WSL/驱动/GPU、APT 源前先列出计划并请求确认。
- ROS 2 与 LeRobot/PyTorch 用不同 Python 环境；不要混装。
- 始终记录安装命令、软件版本、错误日志、解决方法和复测结果。
- 禁止将 token、API Key、私有数据写入 Git 仓库。
~~~

## 6. WSL 备份与导入：修正位置参数

原始笔记：

~~~powershell
wsl --export Ubuntu22.04 Ubuntu.tar
wsl --import Ubuntu22.04 E:/wsl/Ubuntu.tar path
~~~

正确概念为：

~~~powershell
# 以实际 wsl -l -v 列出的发行版名称为准
wsl -l -v
wsl --shutdown

# 把发行版导出成 tar 文件
wsl --export Ubuntu-22.04 D:\wsl-backups\Ubuntu22.04-20261022.tar

# 可将备份导入到一个新的发行版实例（示例：不是覆盖原实例）
wsl --import Ubuntu22Backup D:\wsl\Ubuntu22Backup D:\wsl-backups\Ubuntu22.04-20261022.tar --version 2

# 检查是否导入成功
wsl -l -v
~~~

`wsl --import <发行版名> <安装目录> <备份文件.tar>` 才是正确参数顺序。注意：导入的新发行版默认登录用户可能成为 root，后续应检查并配置默认用户。备份中可能包含 SSH 私钥和服务配置，需妥善保护 TAR 文件。

## 7. 环境分岔：到底继续 Ubuntu 22.04 还是迁移 24.04？

| 实际情形 | 建议 |
| --- | --- |
| 机器当前为 Ubuntu 22.04 且已经稳定 | 先继续使用；ROS 2 使用与发行版相配套的 Humble；DSH 可独立配置 |
| 还没安装 ROS 2 / 训练环境，打算长期使用 Jazzy | 优先新增 Ubuntu 24.04 实例，不覆盖旧 22.04 |
| 想使用 ROS 2 Jazzy 官方 apt 套件 | 选择 Ubuntu 24.04 |
| 想跑轻量 PushT / LeRobot | 独立 Python 环境，可先验证而无需 Isaac Sim |
| 需要重型 Isaac Sim RTX 图形 | 在检查 GPU/驱动后优先 Windows 原生安装 |

**目前未核验**你实际安装的是哪个 Ubuntu。先贴出本地运行结果再做版本迁移，而不是假设已经是 24.04。
